## 3. 20 Hz 预算判定

20 Hz ⇒ 50 ms/帧。

| 判据 | 结果 |
|---|---|
| p50 20.1 ms | 通过 |
| p95 30.4 ms | 通过（余量 19.6 ms） |
| p99 47.1 ms | **贴近上限**，仅余 2.9 ms |
| max 117.3 ms | **不通过**，会丢 1–2 帧 |
| 严格"每帧 ≤50 ms" | **未达到**（超 50 ms 的帧存在） |

## 4. 与历史 CUDA-NDT 的对比（仅参考，不作结论）

任务给出的历史 CUDA NDT 匹配耗时 p50 1.13 / p95 1.78 ms。
本轮 CPU GICP 匹配 p50 5.72 / p95 12.53 ms，约 5–7 倍。
但**整帧 p50 20.1 ms 中 GICP 只占 5.7 ms**，其余是 Python 驱动与 15D 开销，
因此"换 GPU GICP"不是当前瓶颈。

## 5. 瓶颈判定（Q11）

按 p50 拆分：

1. **Python 驱动与 15D 更新**（约 14 ms）—— 最大项；
2. GICP 匹配（5.7 ms）；
3. Deskew 与 I/O（含在剩余时间内）。

因此瓶颈是**驱动/滤波器的语言与实现**，不是配准算力。这与 Phase AW 的
"CPU GICP 在此负载 P95≈8.36 ms，整环 P95≈26.97 ms"一致。
