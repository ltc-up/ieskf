# Reuse boundary and engineering assumptions

The independent C++ JSONL service links the existing MIT small_gicp headers at the preserved vendor revision. It reuses PointCloud, KdTreeBuilderTBB, `estimate_covariances_tbb`, GICPFactor, ParallelReductionTBB, LM, termination and rightSE3 update. Historical settings: TBB arena4, kNN20, distance4m, max50 iterations, translation1mm, rotation0.1deg. Reported native iterations field is the upstream zero-based last iteration index. No extra Source/Target downsampling is applied beyond frozen Deskew/frontend and original map Target preprocessing.

Static global Target tree and local covariance are prepared once, persisting across frames. Source tree/covariance are rebuilt from each actual own-state Deskew output. Original active cylinder/Z bounds are enforced through target-correspondence rejection. Target covariance neighborhoods can extend outside ROI, unlike rebuilding a cropped tree; Source/nearby matched points are normally well inside the120m boundary. This is a disclosed representation difference, not identical NDT/GICP objectives. No live Source enters Target.

Upstream covariance setter **replaces local eigenvalues with (1e−3,1,1)** while retaining eigenvectors. This is a planar geometry metric, not measured physical point-noise covariance. The complete GN Hessian and b are refreshed at final pose after optimization, with refreshed inlier count/cost. `optimizer_last_H` is logged separately. Right perturbation order is `[φ_body,ρ_body]`, `T←T exp(δ)`; pose output is map/base. Full coupling is preserved for geometry diagnostics; inverseH is not submitted as calibratedR.

GICP15D baseline uses a preregistered fixed engineering covariance translation standard deviation0.5m and rotation standard deviation1deg on each axis, all6DoF. More precisely position variance0.25m² and angular variance(π/180)²rad². “Conservative” describes a declared runnable assumption, not a proven error bound. It is not derived from raw GICP score, Native scaling or GNSS fitting. Original full15D IMU/wheel/Q/Bias/H/lever/Joseph/reset and500ms delayed replay remain unchanged. Nonconverged/invalid candidates never become measurements; no NIS hard cut is introduced.

Backend selection: `--backend ndt_legacy|gicp|ndt_fixed`; ndt_fixed is an actual causal matched-R control using exactly the same0.5m/1deg model. Original A and historical NativeB remain intact. No simultaneous independent fusion of NDT and GICP from the same cloud occurs. AV remains optional historical context only.

New runtime memory handling streams ledger/state/wheel JSONL and retains only first/last Python records; immutable long-lived input heap is frozen for GC scanning while GC remains enabled. It neither changes sensor Header/arrival order nor replaces perf-counter completion with an ideal clock. Fresh legacy40 exactly reproduces original seed/P/final/K/delta. Timed200-frame GICP replay agrees with its actual baseline within1.14e−13 pose/8.89e−16P, same accept events; runtime instrumentation has no observed numerical effect. No enlarged history or intentionally dropped slow frames.

Capacity/ROI caveat: the direct upstream service reuses the historical audit API route, not production GicpRegistration’s500k activeTarget cap. The static908013-point Target is allowed under a separate20M file-safety limit and measured resource budget. Global nearest-neighbor search followed by ROI rejection does not retry the next in-ROI neighbor, and global covariance neighborhoods can span the ROI edge. This may withhold some edge correspondences; it is not exactly the clipped-tree method. Source/Target identity and these modelling differences are recorded rather than claimed identical. Runner and evaluator additionally verify actual small_gicp backend identity before using/tagging GICP observations.

The fixed engineeringR is declared directly in the selected observation coordinates (map translation and prior-anchored SO3Log). It is not claimed to be an independently propagated body-frame measurement-noise covariance. A physically calibrated pose covariance would require the corresponding full Log/lever/chart propagation, as existing native_pose_R already implements for its declared source convention.
