# Separate actual realtime harness (not yet GPU executed)

`realtime_runner.py` is a new file and does not modify the frozen serial runner or A strategy runtime. It consumes original bag events in recorder availability order and real wallclock time, retaining the full 130 s history and legal 135 s initialization. A0 uses the unchanged C5 realtime baseline; this new harness explicitly accepts only A1/A2.

One GPU worker performs unchanged Deskew, original Align, all A1/A2 geometry/line-search evaluations and covariance construction. Source filenames are immutable and versioned across retries and retained for the 500 ms checkpoint horizon. The main event thread continues IMU/Wheel and bounded LiDAR input queuing (maximum ten pending scans). The existing real ROS `RealOutput` publishes actual 100 Hz committed read-only snapshots and loopback receipts while the independent process publishes clock. No saved posterior or serial trajectory drives these publications.

A worker binds its complete result to the exact pre-observation prior hash. Before admission, the event thread retrieves the actual historical prior. If it differs, the complete geometry job is resubmitted asynchronously with fresh causal Deskew history, a new Source version, and the same raw scan. No geometry callback runs on the event thread. A matching result commits once through a unique-ID/information-group ledger and replay; the prepared observer rechecks the exact prior hash.

There is an explicit current limitation: a newly arriving event can change the prior of an already committed historical geometry observation. The prepared observer refuses to reuse that old result and raises `HISTORICAL_GEOMETRY_REQUIRES_ASYNC_REBUILD`. The harness reports the failure/NO-GO rather than silently freezing stale geometry or hiding synchronous GPU work in the IMU/Wheel thread. A general asynchronous rebuild of multiple already committed geometric transactions is not implemented in this harness. Pre-admission version retries are supported; full post-admission async historical geometry rebuild is not claimed. If encountered, this is an experimental failure that requires further engineering, not permission to change the algorithm or model.

Measured records retain full P, prior and Source versions, all algorithm diagnostics, GPU-worker and main-commit costs, real completion/availability latency, input delivery lateness, queue/resource failures, 100 Hz state age/deadline and actual subscriber receipts. A 100 ms input delivery violation, ten-scan queue overflow, expired historical prior, resource violation or repeated prior-version churn terminates honestly with preserved artifacts. These safeguards measure practical failure rather than claiming 20 Hz simply because a timer exists.

CPU tests verify exact-nanosecond prior binding, safe copying, one-transaction ledger behavior and explicit post-commit prior-change failure. Import/bytecode checks pass without launching ROS/GPU. Actual scheduling, full input completion and 50 ms/100 Hz performance remain unvalidated until the coordinator schedules the GPU run.
