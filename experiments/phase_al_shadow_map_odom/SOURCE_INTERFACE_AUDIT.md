# Production interfaces — read-only audit

Verified legacy paths: lidar_ndt_v1/src/ndt_process.cpp and ndt_component_node.cpp, NDTProcess::GetNDTMatchingData. Legacy dispatch stamps output from cloud Header and publishes map-from-base pose; covariance fields are score-derived, not calibrated. Legacy subscriptions to three individual clouds are commented; fused-cloud subscription is active. Single-sensor preprocessing branches exist, but this does not prove active single-LiDAR operation.

Also found current modular lidar_ndt/src/{ndt_process,ndt_registration,ndt_component_node}.cpp and include/lidar_ndt/{frame_execution,ndt_publication}.h. Current component builds explicit frame context, nearest-time seed and native registration status; publication distinguishes measurement/fallback/no-message. A published fallback is not an NDT observation. Current local configuration selects CUDA; legacy v1 configuration selects CPU. Runtime launch/parameter selection was NOT observed; neither file alone proves which binary was running during historical capture. Restricted code was read, not copied or modified.

Deskew: lidar_deskew/src/lidar_deskew.cpp publishes sensor_msgs/PointCloud2 on configurable fused-cloud output; default /sensor/lidar_fusion/points. lidar_pose_estimation.cpp supplies motion pose. AL uses frozen native-reference Source, not regenerated Deskew. Each frame's recorded source_cloud_identities gives three contributing raw cloud records; adapter carries opaque source aliases, not assumptions about currently active sensors. The recorded base pose is formed through GeometryFactor.transform (IMU origin minus rotated lever); source, observation and local pose use the same native reference timestamp.

Production NDT prior subscribes nav_msgs/Odometry on /localization/pose_twist_fusion_filter/kinematic_state. ekf_localizer::callbackNDT subscribes /localization/ndt_pose and queues it when use_ndt is enabled. Converter can also select NDT orientation. Therefore this output is NOT qualified as independent odom; exact runtime enable state is unknown. AL instead uses fresh research15D IMU/wheel recursion with historical fused pose ONLY at initialization. Bias means/noise are historical research assumptions, not calibrated sensor statistics. Local frame is a fixed initially map-aligned research odom, never reset by subsequent map observations.

GNSS source interfaces found in ekf_converter: /vectornav/raw/gps and /vectornav/raw/gps2, vectornav_msgs/msg/GpsGroup; converter calls LLA→ENU and applies reference conventions. Values of private origins/levers are not published. Bosch sensor_msgs/Imu, Kistler custom velocity/status and wheel custom messages exist; AL replay consumes already extracted historical scalar wheel events, not a new Kistler/IMU data adapter. Datum/antenna/time/statistical qualification for GNSS remains a later audit, not assumed from topic names.

Production worktree already has a user modification in lidar_ndt configuration; it was left untouched. No production build, source rewrite, parameter update or TF ownership change was performed.
