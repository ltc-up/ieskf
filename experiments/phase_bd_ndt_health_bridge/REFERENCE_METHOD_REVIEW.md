## Transferable mechanisms and limits
Tracking/recovery policies separate accepted map correction, odometry bridge, alignment diagnostics, rejection streaks and local reacquisition. Seed guards can bound an untrusted correction but cannot prove correctness. Defaults differ from deployment parameters: inspected lifecycle source uses 0.5m/15deg with five warmup accepts, not a universal 0.3m rule. Neither distance nor acceptance/rejection counts transfer to 20Hz racing: 30 scans mean 1.5s, about 52.5m travelled at 35m/s. Correction limits must describe prediction uncertainty and scan timing rather than total travelled distance.

Global localization documentation distinguishes BBS ranked candidates, local NDT refinement, candidate walking and aged results. It explicitly reports seconds on validated windows, not millisecond recovery. Ranking a single scan is insufficient against corridor aliases; temporal/second-query validation and candidate age must be retained. No automatic high-speed reset is authorized. Public Go2/Koide/Istanbul tests are evidence for those conditions only. `pose_covariance.md` describes floor-plus-fitness calibration on public datasets and explicitly limits its interpretation; it does not validate racing R or a wrong-peak detector.

Rust `voxel_grid/search.rs` builds a tree over Gaussian means and performs Euclidean radius queries. DIRECT7 selects the containing grid cell and six axial neighbors. Supports differ, hence sums, gradients and Hessians generally differ even if each pair uses the same Gaussian expression. Radius queries can smooth some cell-boundary effects but retain radius-support discontinuities; repeat guardrail disambiguation is unproven. Multi-start can expose distinct peaks, but agreement does not prove the common peak correct. Batch execution changes resource cost, not this inference.

`degeneracy.rs` negates score Hessian, symmetrizes and eigendecomposes translation/rotation blocks separately. It avoids mixed-unit full-matrix conditioning but omits coupling. BD will retain XY-yaw coupling using an explicit length scale and validate chart/sign/derivatives before interpreting it. `covariance.rs` local inverse curvature cannot capture separated wrong modes. Do not replace production R.

## Final follow-up to the initial audit

The original12632 trace, CPU OFF flag,21-start CSV and current independent KD experiment have now been inspected; see P0_HISTORICAL_EVIDENCE.md and NEIGHBOR_SEARCH_COMPARISON.md. The initial-review pending wording records the initial state, not a claim that every historical lead was resolved. Exact DIRECT27 latency/oscillation and primary historicalq9/q25/NIS details remain explicitly unverified; no decision is justified from those unverified numbers.

Reference questions: prediction state and last accepted map pose are separate anchors; bridge publication composes frozen accepted map-from-odom with fresh external odom. Rejection preserves motion prediction and does not refresh map observation covariance. Correction guards and generation checks stop stale in-flight scans undoing resets. Continuous rejection feeds tracking/reacquisition/recovery policies; global supervisor requires persistent loss request, debounce, cooldown, maximum attempts and recovery evidence rather than copying a universal30-count rule. A second fresh query compares the candidate with the localizer at candidate scan time; weak/indistinct fixes cannot confirm or reseed. The docs describe a ground-truth-confirmed Koide kidnap run and also a25–28m alias false confirm, showing why confirmation alone was insufficient. These are documented reference experiments, not newly replayed racing results.

Rust radius CPU search is KD-tree over Gaussian means; some GPU/batched paths use brute-force radius kernels with bounded neighbor storage. That implementation distinction prevents treating the repository name as proof of a replaceable KD backend. Its separate-block degeneracy analysis discards cross coupling; this phase uses an explicit scaled coupled3D subspace instead. Multi-NDT/batch can expose competing numerical modes at real memory/compute cost, but cannot certify a common mode. More-Thuente can damp oscillation or retain a local basin; local score descent and global matching correctness remain separate.
