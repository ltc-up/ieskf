# 性能、采样成本和显存

Fitness OFF，两种子/所有N仍同P3二进制和原共享库。20组A align单测约0.405–4.807ms；随机5k/10k约0.598–6.186ms。FULL64/66本次OFF为11.361/16.863ms；FULL60/65/76沿用P3稳态中位2.402/11.809/14.011ms。后三者为历史同参数OFF但不同时段，不是本轮严格配对计时。P2 trace+FitnessON耗时不混入OFF性能表。

**空间排序73.404–76.445ms/原始扫描，随机排列约0.95–0.97ms。** 同帧同种子的四档共享一次排序；离线摊销不能使真实在线新扫描免费。Python np.unique/lexsort完整排序为本研究原型，无GPU采样或线上复用证明。单是空间采样就超过50ms，所以当前端到端方案NO-GO；不得仅用缩短的align宣称可部署。

采样索引排序、子集物化、临时bin写入、覆盖统计及服务时间均分项保存。原Source只读复用；唯一current_source.bin反复覆盖本轮临时缓冲，不保存各组点云。每个记录保存索引/内容SHA，重建子集可复核。覆盖统计本身是离线诊断成本，不能悄悄算成在线采样或从完整周期中隐去。逐组sampling_order_ms是完整排序成本，不能把同一次排序重复累计四次，也不能将其作为0忽略。

align含GPU上传、优化线性化/邻域、梯度/Hessian、SVD/GLL、内部Native质量及同步；未导出每次迭代事件/Native内部独立计时，标UNKNOWN。可报告align/次数作含固定开销的摊销量，但不称实际单迭代kernel时长。额外Native质量查询独立有quality_extra_ms，不代替内部质量计时。P3前后device同步仍保留，表中不将嵌套区间重复累计。

两次进程会话首调用包含冷启动/Target构建，prepare_ms在原响应记录；不删失败帧，不算实时P95/P99。每组只做一次，不同种子是不同输入，不能当相同输入的性能重复样本。多组align不单调（小Source也有调度/首次分配波动），只观察趋势。

所有72次nvidia-smi返回该Matcher进程常驻显存168MiB。此为请求结束后的进程级/取整值，不是峰值或纯Source buffer，不说明点数变化零显存代价；采样/覆盖统计和nvidia-smi查询在CPU侧，其耗时不在align里。

无真实Deskew、15D传播/延迟更新和ROS控制链。完整系统20Hz仍未经本轮验证。RESULTS.csv逐组包含N、采样/物化/写盘/align/额外质量/显存，Source读取及冷启动详见私有预注册/原响应。
