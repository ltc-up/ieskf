# Delay and lifecycle
PoseDelayReplay extends the previously verified AO checkpoint runner without modifying old modules/results. Sensor events, reference clock events and external observations have stable priorities; held IMU age is preserved during a reference/observation time advance. Historical NDT tau is inserted within500ms, and suffix state/P updates affect subsequent Deskew/seed. Duplicate Source groups cannot be submitted again under another message ID. Tests compare Header and delayed external-update order including full P.

Clock ticks do not create new independent IMU measurements. The same reference grid is present in A/E, giving exact native-time no-map parity. Startup map/GPU initialization precedes input-time activation and is reported separately; EMPTY_SOURCE initialization is not a valid pose or a fusion update. Persistent Deskew avoids creating a new CUDA context for every frame. Cold/batch failures remain archived.

Recorded LiDAR receipt time and measured compute delay are used, but sensor availability remains Header-idealized. This is offline real-data causal feedback, not proof of live ROS2 callbacks/queues or production smoothing equivalence. No production TF/node is started. Native-time fields inherited from legacy bindings can have submicrosecond float quantization; new continuous extraction uses exact ROS Header integers. Independent hardware-clock alignment is still unverified.
