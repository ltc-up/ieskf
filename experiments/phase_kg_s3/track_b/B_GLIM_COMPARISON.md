# GLIM comparison and actual implementation boundary

Read source: GLIM commit `1a197c999e4865f5cab7c9cd25474128413ebbca`, `src/glim/odometry/odometry_estimation_gpu.cpp`; gtsam_points commit `8e94654558dfbe7ddb0341de300daaf17e25ee02`.

GLIM `create_frame`:86–106 adapts base voxel resolution from median point distance, creates levels using geometric scaling. The reviewed default config uses .25–.5 m adaptive base, two levels and factor 2. `create_factors`:128–205 connects the current pose to recent poses (default full_connection_window_size=2) and older keyframes; each target level creates its own native VGICP factor with surface validation. Keyframes outside fixed-lag variables use fixed unary target pose; inside use binary factors. This is not three scans concatenated into one Target.

`update_keyframes_overlap`:212–294 uses union overlap to insert, low-overlap removal after capacity overflow and contribution versus redundancy scoring. Defaults max15, insert .7/remove .01. Our B-K implements a bounded three-frame CPU occupancy-based analogy with actual local O trajectory; no claim to run native GLIM optimization, IMU preintegration, native overlap Gaussian lookup or default 15-keyframe system.

Native `include/gtsam_points/cuda/kernels/lookup_voxels.cuh`:42–48/70–77 rejects when transformed point ray normalized dotted with rotated SOURCE normal is >.174. It is signed, measured in target-local coordinates and is not a source/target normal-angle check. The inline comment saying cos10 conflicts with the actual constant; use actual .174 (approximately cos80). Native normal estimation flips only for point dot normal >1.0 (`normal_estimation.cpp`:26), whereas our diagnostic explicitly orients source-facing normals. This difference is recorded rather than silently calling the result native parity.

Implemented: B-K selection with continuous local state and real native NDT matching; separate CPU signed-surface and two-resolution occupancy diagnostics with tests. Implemented additional separately named B-K-MR: coarse NDT 3 m then fine NDT 1.5 m, identical Source/real Target and B-K history, two independent native sessions. Coarse output is only a fine seed; fine failure returns prediction and never promotes coarse. The outer frozen validator compares fine output against original local prediction. Native VGICP optimization, surface filtering inside CUDA NDT and joint graph estimation remain NOT implemented. Occupancy diagnostics do not satisfy a claim of multiresolution registration. Applying the GLIM filter to NDT would alter the actual target score support; changing resolution to 3→1.5 would be a named additional registration comparator. B-K-MR is the explicitly authorized additional registration comparator; Surface remains support-only and does not change any NDT score.

Stage1 differences: compare.py:70–75 concatenated last up-to-three saved cropped Source clouds into earliest-base Target using gyro/Wheel E; ROI disabled with ±10000 z and 120 number. prepare.py:21 used .5 CPU factor resolution, max3/1s, surface_validation=false. factor_diagnostics.py:27–33 evaluated a factor at supplied motion, not optimized relative odometry. The old implementation does not fulfill the present dense previous-frame Target or continuous B0 chain.

The complete first two KINEMATIC_BK continuous runs did not log actual surface-normal diagnostics. That evidence is explicitly NOT_LOGGED, not zero and not successful validation. A new named passive 713 entrypoint has been reviewed: it observes only the existing baseline plus three preregistered fixed-history probe calls, transforms Target and candidate by inverse(actual previous O pose) into the historical base, and computes source-facing signed-ray occupancy support. Five tests verify rigid-gauge invariance, the wrong-O-origin counterexample, original object identity/no mutation, unchanged registration count and independent sidecar closure status. Real selected-case surface results remain pending execution; no surface mask modifies the NDT objective or acceptance.
