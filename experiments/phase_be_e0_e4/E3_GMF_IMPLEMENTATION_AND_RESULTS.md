# E3 — Independent 15D Gaussian bank

The opt-in `GaussianBank` maintains two branches in the executed experiments. Each branch deep-copies its own nominal 15D state, full P, IMU/velocity event history, pose ledger and checkpoint. CUDA deskew and subsequent matching use that branch's predictions. The optional third-branch capacity is an API bound, not an evaluated three-branch result.

A converged NDT/GICP displacement exceeding the documented engineering separation test can instantiate the second branch. This test demonstrates different poses, not mathematically distinct attraction basins. The initial split divides prior mass; it does not manufacture evidence. Thereafter each branch uses its assigned matching backend. No mean between disjoint poses is output.

For one common held-out frame group g, a clipped squared nearest-map distance supplies competing costs c_i. The update is `log w_i <- log w_i - min(c_i-min(c),4)`, followed by log-sum-exp normalization. A frame is counted once, not once per backend, and is scored only when the branch updates actually admit it. This is a generalized-Bayes engineering score; map/model/time correlations remain, and these are NOT calibrated posterior integrity probabilities. Native NDT and GICP Fitness are never compared. Held-out points share the map and deskew model, so validation is not an independent sensor.

Main-mode selection requires log odds above 2 for three confirmations. These are explicit research lifecycle settings, not racing safety limits. Runtime conservatively retains both modes instead of deleting a mode on a single prediction discrepancy or possible sideslip. API pruning and effectively identical-state/history merging exist; arbitrary regeneration after multi-branch evidence requires a new epoch and is deliberately rejected. Modes with different histories are not moment-averaged.

Historical evidence has its own ledger. Revoking retained pose data also removes its frame score and recomputes weights from the epoch prior and remaining evidence. A tombstone prevents the same frame returning as new evidence. Subsequent held-out data were acquired under the original deskew history; weight replay does not recompute every historical cloud/match. Thus exact filter rollback tests do not establish full statistical counterfactual equivalence of the nonlinear matching pipeline.

See `aggregate_results.json` and `ACCURACY_COMPARISON.md` for executed frame counts, switches and proxy errors. See `PERFORMANCE_COMPARISON.md` for inclusive timing. The bank is an implemented research prototype, not a statistically calibrated or production-qualified estimator.

Final code review tightened unused merge APIs to check the entire nominal state (including both biases), timestamp and exact event payload history, and to require a new evidence epoch before merging scored modes. The runtime does not use merging/pruning; the safeguard is unit-tested rather than credited as a real-data accuracy improvement. Final rollback code also removes scores for later observations invalidated by replay, not just the originally revoked ID. Per-run source hashes distinguish earlier executions; selected single-lap ledgers show no such additional cascade, so their five direct revisions do not validate an unexercised cascade case.

The executed single lap retains two branches for all1468 frames and makes zero main-mode switches. Its selected NDT trajectory has the same0.577m75ms reference RMSE as the matched control. All577 proxy-good selected observations are accepted; the one proxy-bad selected observation is also accepted. This is not a successful wrong-mode detector. Scores update only when both branch observations are admitted, so a failed branch can freeze relative evidence; retaining its state is not proof it can safely recover the true mode.

The revised GMF three-lap run stops at4052/4134 frames; the robust variant stops at4035/4134. Both terminate on INPUT_OUTSIDE_FORWARD_HORIZON after severe compute backlog/measurement expiry. The safety guard is preserved. Prefix accuracy/timing is in partial_results.json, never mixed with full-loop success. The final API version is additionally tested in a30-frame integrated run; this does not turn failed long runs into passes.

A two-branch framework is useful as an experimental container, but this generalized-Bayes implementation has not demonstrated a real-data mode-selection gain or20Hz robustness. It is NO-GO for production and for adding a third branch before evidence calibration and bounded computational cost are resolved. The Python/forensic-IO timing failure does not prove all compiled GMF designs are intrinsically too expensive.
