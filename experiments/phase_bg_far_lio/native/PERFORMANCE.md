# 性能与完整周期

本次是原始recorder到达顺序的1×墙钟ROS重放调度，不使用共同到达时刻仿真。只读输入准备、融合、DDS、Native配准、内部去畸变、质量、EKF及发布都实际执行；没有容器开销。sensor header到录包可用时刻已有约56–69ms延迟，必须与收到原始输入后的处理时间分开。

这些组件相互嵌套，不能把云回调、pipeline和registration相加。EKF step/delay/publish为源码明确的微秒，GICP/回调字段为毫秒；TSL消息stamp为0，组件只能按整个窗口聚合，不假称逐帧阶段精确配对或CUDA event。GPU kernel、独立传输/同步、CPU预处理与质量全部细分仍有UNKNOWN。

历史15D耗时来自旧保存数据：包含不同Python/服务/历史传播/IO工作负载，未做同次运行的配对测量；不能仅凭上表宣称FAR核心更快/更慢。
